# Артефакты

`archive/` — полный архив сообщений каналов тревог (веб-превью t.me/s), по каталогу на канал и файлу на месяц:
`archive/{канал}/YYYY-MM.tsv` — строка на сообщение: `канал \t id \t unix-время (UTC) \t текст` (переводы строк — `\n`).
`archive/{канал}/.state` — состояние докачки.

Скачивание и докачка (повторный запуск продолжает с места остановки и дописывает новые сообщения):

    Radar --archive-fetch artifacts/archive [канал ...]

## Продакшн-формат

`archive-pack/` — тот же архив в виде для поставки: файл на месяц по всем каналам и манифест.
`archive-pack/YYYY-MM.tsv.gz` — gzip, строки в формате выше, без повторов (канал, id), по времени.
`archive-pack/manifest.json` — `format`, `created` и по месяцам: `month`, `file`, `messages`, `bytes`,
`sha256` (несжатого содержимого), `channels` (сообщений по каналам), `from`/`to` (unix-время первого/последнего).

Приложение читает оба формата: если в каталоге архива есть корректный `manifest.json` — пакеты, иначе каталоги каналов.
Каталог архива: `RADAR_ARCHIVE`, иначе `artifacts/archive-pack` (если в нём есть манифест) или `artifacts/archive`
выше каталога программы, иначе `archive-pack`/`archive` в каталоге данных приложения.

    Radar --archive-pack artifacts/archive artifacts/archive-pack   # упаковка; неизменившиеся месяцы не перезаписываются
    Radar --archive-verify artifacts/archive-pack                   # проверка файлов, SHA-256 и числа сообщений
    Radar --archive-unpack artifacts/archive-pack artifacts/archive   # обратно в каталоги каналов (докачка в CI)

Опубликованный архив — релиз [`archive`](https://github.com/Escorp-Dynamics/radar/releases/tag/archive) (обновляется
ежедневно workflow `archive`). Приложение без своего архива загружает его в `{данные}/archive-pack` и докачивает только
месяцы с изменившимся SHA-256; манифест записывается последним.

Упаковка не теряет данные из-за неполного источника: месяцы, которых нет в источнике, остаются в архиве с прежним
пакетом, а если в месяце стало меньше сообщений, выводится предупреждение. При чтении отсутствующий или оборванный пакет
(сообщений меньше, чем в манифесте) — ошибка, а не молча неполные данные: иначе они попали бы в статистику и её кеш.
Докачка дописывает месячные файлы, не склеивая новую строку с оборванной последней.

## Проверка движка по архиву

`validation/engine-audit-months.tsv` — итоги `--engine-audit` по месяцам (треки, развороты, петли, прогнозы).
Кеш геокодера берётся из `RADAR_GEOCODE_CACHE`, иначе — из каталога данных приложения; для воспроизводимых итогов
аудит идёт с зафиксированным снимком `validation/geocode-audit.tsv` (растущий кеш пользователя меняет треки на ±1–2):

    RADAR_GEOCODE_CACHE=artifacts/validation/geocode-audit.tsv Radar --engine-audit месяц.json итог.tsv

Полный прогон (≈3,5 мин на 8 ядрах): выгрузка `archive-pack` по манифесту в JSON по месяцам, аудит всех месяцев
параллельно и сводка — в формате таблицы. Рабочий каталог — `RADAR_AUDIT_DIR` (по умолчанию `/tmp/months`), сборка —
`RADAR_AUDIT_BIN` (по умолчанию Release в `/tmp/raudit`: в ~1,7 раза быстрее Debug, вывод тот же), параллельность —
`RADAR_AUDIT_JOBS` (по умолчанию по числу ядер, ~250 МБ памяти на месяц); `RADAR_AUDIT_ALLTRACKS=1` выводит все
треки с координатами и источниками.

    tools/run_audit.sh > artifacts/validation/engine-audit-months.tsv
    tools/audit_export.py [каталог]    # только выгрузка
    tools/audit_summary.py [каталог]   # только сводка по готовым логам
    python3 -m unittest discover -s tools -p 'test_*.py'   # тест разбора логов; входит и в `dotnet test` (ToolsScriptTests)

Столбцы таблицы (метрики качества треков — только по трекам из 3+ отметок, по последнему состоянию трека):

| Столбец | Что считает |
|---|---|
| `сообщ`, `треков`, `3+т` | сообщений в месяце; всех треков; треков из 3+ отметок |
| `развор` | разворот трека более чем на 120° между отрезками от 8 км |
| `петли` | путь длиннее 40 км и вдвое длиннее прямого расстояния |
| `к_Укр` | трек идёт обратно к линии фронта (в Крыму/на Кубани — назад к точке захода); КАБ не проверяются |
| `к_городу` | то же, но конец у города 100 тыс.+ в пределах 15 км (Белгород, Горловка) — вероятная цель, учитывается отдельно |
| `пуск_впер` | точка пуска лежит впереди по ходу трека, а не позади |
| `прогн_назад` | прогноз (стрелка/пунктир) ведёт назад к линии пуска или против последнего отрезка; цели и курсы, названные в свежем сообщении, не считаются |
| `прогнозов` | треков БПЛА/ракет с прогнозом, проверенных на `прогн_назад` |
| `отбоев` | применённых отбоев |
| `холост` | отбой не снял ни одной тревоги |
| `завис` | отбой по всему региону, после которого остались тревоги того же канала |
| `широк` | отбой по пунктам снял тревогу без этих пунктов |
| `отброш` | отбой не применён (не распознаны регион/пункты) |
| `дубли` | одновременно активные совместимые тревоги по одной местности (выборка каждые 10 сообщений) |
| `репост` | один текст (±20 мин) в разных активных тревогах |
| `точк_дубл` | один пункт в нескольких совместимых активных тревогах |
| `к_Укр_2т` | треки из 2 отметок, идущие к линии фронта (справочно) |
| `без_курса` | треки, показанные на карте значком без направления и скорости (`Track.UncertainHeading`) |

Целевые значения: `развор`, `петли`, `к_Укр`, `к_городу`, `пуск_впер`, `прогн_назад`, `завис`, `широк`, `дубли`, `репост`, `точк_дубл` — 0. Регион отбоя без названных в нём пунктов
(«Отбой … Приазовье ⏎ Крым и Севастополь») считается отбоем по всему региону.
